# План подготовки к хакатону «Время IT 2026»

План собран по двум чатам о хакатоне: исходному обсуждению подготовки и чату с интенсивным планом и вопросами по FastAPI/SQLAlchemy. Учтены текущая роль backend + база данных, база по C++, около 75% курса SQL Карпова, первый хакатон и то, что Python/FastAPI/SQLAlchemy пока осваиваются на практике.

## Цель

К защите 17–18 октября помочь команде довести до демонстрации один цельный пользовательский сценарий: запрос из интерфейса проходит через API в базу, данные сохраняются, а результат виден пользователю. Технологический стек команды важнее учебного примера: если команда выбрала другой язык или фреймворк, выполнять те же задачи в нём.

Официальные условия требуют работающий прототип и один законченный сценарий; выбор технологий остаётся за командой. Темы связаны с музыкальными сервисами: совместный плейлист, клуб концертов, музыкальная комната, караоке, аудиовизитка или открытка. [Страница хакатона ГУАП](https://guap.ru/c/itforum/programm/hakaton_2026)

## План по дням

### 12 октября — разобраться в проекте и запустить основу

- Узнать выбранный командой стек, способ запуска и свой конкретный участок.
- Запустить проект по инструкции, открыть `/docs` (если используется FastAPI), выполнить один существующий запрос.
- С командой выбрать самый короткий законченный сценарий и выписать данные, которые для него нужны.
- Согласовать с frontend названия полей, URL, HTTP-методы и форму JSON-ответа.
- Если API ещё нет, сделать `GET /health` и один простой endpoint на временных данных.

**Результат:** проект запускается, понятны границы задачи и первый endpoint.

### 13 октября — модель данных и чтение

- Нарисовать таблицы, связи, первичные/внешние ключи и ограничения.
- Для плейлиста подойдут `communities`, `tracks`, `votes`; для другого кейса заменить сущности по пользовательскому сценарию.
- Реализовать подключение к выбранной БД, модели и чтение записей.
- Проверить пустой результат и запрос записи по ID.

**Результат:** API получает реальные данные из БД.

### 14 октября — создание и изменение данных

- Реализовать нужные `POST`/`PATCH`/`DELETE` методы и схемы проверки входных данных.
- Обрабатывать отсутствующую запись (404), неверные поля (422) и конфликт ограничений.
- При голосовании обеспечить уникальность пары `(user_id, track_id)` ограничением в БД.
- Проверить, что данные остаются после перезапуска приложения.

**Результат:** пользовательское действие меняет сохранённые данные.

### 15 октября — интеграция и устойчивость

- Пройти сценарий от frontend до базы вместе с командой.
- Сверить CORS, форматы JSON, коды ответов и названия полей.
- Добавить миграцию, только если схема уже меняется в ходе командной разработки.
- Проверить основной сценарий и 2–3 ошибочных случая.

**Результат:** backend согласован с интерфейсом и переживает типичные ошибки.

### 16 октября — чистый запуск и репетиция

- Проверить запуск по README на чистом окружении или другом компьютере.
- Подготовить демонстрационные данные и резервный вариант показа.
- Убедиться, что тестовый сценарий не требует ручного исправления данных.
- Репетировать объяснение своей части: таблицы → endpoint → запрос к БД → ответ.

**Результат:** команда может запустить и показать прототип без импровизации.

### 17–18 октября — защита

- Не добавлять крупные функции перед показом, если они могут сломать готовый сценарий.
- Показать один путь пользователя от начала до видимого результата.
- Быть готовым кратко объяснить схему данных, ограничения и что пришлось упростить.

## Учебные материалы по мере необходимости

Не проходи всё подряд: открывай материал под текущую задачу и сразу повторяй пример в проекте.

1. [FastAPI: учебник на русском](https://fastapi.tiangolo.com/ru/tutorial/) — первые шаги, параметры пути и запроса, тело запроса, модели ответа, ошибки и зависимости.
2. [Pydantic: Models](https://docs.pydantic.dev/latest/concepts/models/) — модели входных/выходных данных, `model_dump()` и `from_attributes=True`.
3. [SQLAlchemy ORM Quick Start](https://docs.sqlalchemy.org/en/20/orm/quickstart.html) — модели, подключение, добавление, чтение, изменение и удаление.
4. Видео Артёма Шумейко: [FastAPI-пет-проект за 50 минут](https://www.youtube.com/watch?v=gBfkX9H3szQ), [SQLAlchemy: Session и ORM](https://www.youtube.com/watch?v=t7ufjzWKVk4), [Mapped и mapped_column](https://www.youtube.com/watch?v=JxL2iu9vpr8), [SELECT и UPDATE](https://www.youtube.com/watch?v=A72VICB-fjw). Смотри нужные фрагменты, а не весь материал подряд.
5. [PostgreSQL: вводное руководство](https://www.postgresql.org/docs/current/tutorial.html) — SQL, связи, внешние ключи и транзакции.
6. [Git на русском](https://git-scm.com/book/ru/v2) — ветки и слияние; [Learn Git Branching](https://learngitbranching.js.org/?locale=ru_RU) — интерактивная практика.
7. [FastAPI: тестирование](https://fastapi.tiangolo.com/tutorial/testing/) и [Docker: начало работы](https://docs.docker.com/get-started/introduction/) — только когда базовый сценарий уже работает и это нужно команде.

## Задания для закрепления

Выполняй на учебном API общего плейлиста или адаптируй под кейс команды. Сначала сделай самостоятельно, затем сверяйся с документацией.

1. **Endpoint и валидация.** Добавь `POST /tracks` и `GET /tracks/{track_id}`. Используй отдельные схемы создания и ответа. Название не может быть пустым; для неизвестного ID верни 404. Проверь оба случая через `/docs`.
2. **Связь API с БД.** Сохрани трек через SQLAlchemy и получи его после перезапуска приложения. Объясни, где создаются сессия и транзакция и что произойдёт при ошибке до `commit`.
3. **Голоса и SQL.** Создай таблицу голосов с внешними ключами и ограничением `UNIQUE(user_id, track_id)`. Напиши запрос, который показывает треки и число голосов, включая треки без голосов. Попробуй отправить повторный голос и обработай конфликт.
4. **Отладка и командный запуск.** Исправь намеренно сломанный импорт `from sqlalchemy.ext asyncio ...` на `from sqlalchemy.ext.asyncio import ...`. Если используешь асинхронный SQLAlchemy, проверь установку `sqlalchemy[asyncio]` и драйвера (`aiosqlite` для SQLite) именно в активном окружении Python. Затем внеси изменение отдельной Git-веткой, сохрани коммит и дополни README командами запуска.

### Критерий готовности

Можешь без подсказки добавить простой endpoint, объяснить путь данных от запроса до БД, найти ошибку по traceback и показать команде, как запустить свой участок.
